# 文档维护

每个主题只维护一份现行说明。讨论方案后，按确认内容实施，并在同一次交付中更新相关文档。

## 去哪里更新

| 变化 | 对应说明 |
|---|---|
| 命令、环境、停止条件 | usage.md |
| 来源、划分、输入、尺度 | data.md |
| 已实现模型和对照 | model.md |
| 门槛、指标、解释边界 | evaluation.md |
| 新的实际实验记录 | results.md |
| 失败原因与诊断 | diagnosis.md |
| 尚未实施的设计 | next-design.md |
| 文献及第三方借鉴 | references.md、third-party-notices.md |

## 写作与清理

根 README 只作概要与目录。每页先给概要，再链接相关主题和原始证据；正文原则上不超过 100 行。图表明细优先链接已有记录，不在多页重复。

不复制 V1、V2、日期后缀或 archive 文档。删除过时说明前，合并必要的独有结论与来源。版本仅用于识别真实实验；不能为清理文档而删除数据、权重、预测或历史实验记录。

`doc/` 是用户参考资料，不修改。技能说明和第三方自带文件不搬迁。历史实验清单记录当时状态，不因说明移动而改写校验记录；当前交付清单使用现行路径。

## 自动生成范围

当前 `report` 从已有记录更新 results.md；它区分首轮、冻结检查、额外诊断和尺度复核。旧版 `report` 只返回已有首轮结论，不重写文档或实验记录。

尺度报告只更新 diagnosis.md 中标记的尺度小节，保留人工整理的失败分析。日常维护不为刷新说明运行训练或诊断补算。

## 每次交付检查

1. 检查 README 能找到各页，所有本地链接有效。
2. 检查文档中的命令、状态和结果与实际记录相符。
3. 在 qwen3vl 中运行相关检查；文档生成用临时目录验证。
4. 核对受保护资料没有改变，旧报告命令不会生成废弃说明。
5. 区分已完成、仅设计、证据不足，不把检查数量当模型成绩。

每轮研究结束时，提醒维护者人工抽查命令、当前结果与待实施设计。规则不能替代实际核对。

本次已合并首轮说明、第二轮说明和尺度诊断，删除八份重复归档，不保留文档备份。后续直接维护上述主题，不继续累加清理日志。
